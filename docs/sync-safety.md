# Notion 동기화 안전장치

제목 1~4 아래의 하위 블록을 재귀적으로 변환한다. 콜아웃은 하위 블록 표시가 없어도 자식 목록을 조회한다.

모든 원본 조회와 변환을 마친 뒤 검증한다. 검증 전에는 기존 Markdown과 이미지 파일을 덮어쓰지 않는다. 실패한 Actions 실행은 결과를 커밋하지 않는다.

다음 상황에서는 자동 반영을 중단한다.

- 미지원 블록 또는 불완전한 페이지네이션 응답
- 이미지 다운로드 실패
- 이전에 내보낸 Markdown 페이지 누락
- 기존 문서 본문 크기가 20% 넘게 감소
- 읽은 블록 중 변환 경로에서 처리하지 않은 블록 발견
- 중복 페이지 또는 출력 경로 충돌
- 동기화 도중 main 브랜치 변경

기존 파일은 자동 삭제하지 않는다. 매니페스트는 이전 파일 목록을 유지하고, 이번 실행의 페이지별 바이트 수·이미지 수와 처리한 블록 수를 기록한다. 의도적인 페이지 삭제·이름 변경·대량 축약은 원본과 Git 차이를 검토하고 별도로 반영한다. 자동화의 안전 검사를 우회해 처리하지 않는다.

Actions는 고정된 의존성을 설치하고 회귀 테스트를 실행한다. 동시에 실행하지 않으며 최대 실행 시간은 30분이다. 일반 push만 사용하므로 원격의 다른 변경을 강제로 덮어쓰지 않는다.

Notion 색상과 접힌 제목의 표시 형태는 Markdown에서 달라질 수 있다. 파일 크기 검사는 모든 종류의 의미 손실을 검출하지는 못한다. 따라서 변환기를 수정할 때는 Actions 성공 외에 원본 문장·코드·이미지 대조를 수행한다.

## REST API에서 누락되는 콜아웃

2026-09-13 검증에서 `테이블스페이스 구조 요약`과 `테이블스페이스 최종 요약`의 본문은 Notion 연결에서 조회되지만, REST API는 하위 블록 0개를 반환했다. 해당 두 블록만 `scripts/notion-recovery.json`에 원문과 출처를 보존했다. REST 하위 블록이 비었을 때만 이 사본을 사용하고, 매니페스트의 `recoveryCopiesUsed`와 실행 로그에 기록한다. REST에서 자식이 반환되면 현재 원본을 우선한다.

API 문제가 지속되는 동안 이 두 콜아웃의 수정은 자동으로 확인할 수 없다. Notion 연결로 원문을 다시 대조하고 복구 사본을 갱신해야 한다. 이 사본은 실시간 원본으로 취급하지 않는다.
